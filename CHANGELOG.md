# Changelog

## Unreleased

- Completed `todo-experience` Spec 1 Generalized Sync Queue + Lists ([feature doc](docs/features/%5B20260818%5DP1_todo-experience-sync-queue-and-lists.md)): the sync queue and `failed_ops` are now entity-agnostic (`entity_type`/`entity_id`, not Task-only), replay is order-independent with a retry-attempt ceiling, and Lists exist end to end — server `lists` table, client IndexedDB store, full create/rename/reorder/delete, and a `ListSwitcher` UI. Tasks carry a nullable `list_id`. Fixed two real multi-device bugs found via the offline E2E harness: the default "Tasks" list now uses a deterministic well-known id instead of a random one (two devices could otherwise each bootstrap a different default list), and Lists now hydrate from the server on mount (previously a device that never itself mutated a list would never see it). Introduced a layered `Service Client` / `Sync Client` / `API Client` architecture so no UI Component or Hook calls the sync layer directly anymore. Constituent PRs: [#70](https://github.com/jonpham/PSYKL-System/pull/70), [#71](https://github.com/jonpham/PSYKL-System/pull/71), [#72](https://github.com/jonpham/PSYKL-System/pull/72).

## [0.3.0] - 2026-07-29

- Milestone M2 PWA CRUD + Offline-First is complete. The PWA now supports full local-first Task CRUD, offline queueing and replay, an owned Service Worker with Background Sync, Last-Write-Wins multi-device convergence, tombstone delete propagation, and real-stack E2E coverage. Release tag to be cut after PR [#66](https://github.com/jonpham/PSYKL-System/pull/66) merges to `main`.
- Completed M2 Spec 6 Multi-Device E2E Harness ([feature doc](docs/features/%5B20260728%5DP6_m2-multi-device-e2e-harness.md)): `e2e/task_list-offline-sync.e2e.spec.ts` is now active against the real Docker Compose stack and proves two-context storage isolation, offline create replay, Last-Write-Wins convergence, tombstone propagation, idempotent `PATCH` retry, same-key/different-body `409` rejection, and the pending-sync dot. The harness adds reusable Playwright helpers for two devices and IndexedDB inspection. `web_client` now notifies IndexedDB subscribers immediately after enqueue so offline optimistic rows render before Background Sync registration settles.
- Completed M2 Spec 5 PWA CRUD UI Polish ([feature doc](docs/features/%5B20260724%5DP5_m2-pwa-crud-ui-polish.md)): `web_client` now has the full offline-first Task CRUD surface. A private `TaskRow` under `TaskList` provides inline title edit (Enter/blur save, Escape cancel), a complete/uncomplete toggle, and a two-click (3s window) delete confirmation — every mutation routes through the IndexedDB sync queue via `enqueue()`/`enqueueWithReplay()`, never a direct `fetch`. Hydration shows a fixed-height `TaskListSkeleton` (no content shift), an `EmptyState` reads `No tasks yet. Create your first one.`, and `Toast` now covers offline, permanent-fail, and stale-write states. Stale-write is wired end-to-end: `replay.ts` emits `sync:stale-write` when a successful `PATCH` does not echo the sent `updated_at` (a losing last-write-wins race), and the toast tells the user their change was replaced. Constituent PRs: [#67](https://github.com/jonpham/PSYKL-System/pull/67) and [#68](https://github.com/jonpham/PSYKL-System/pull/68).
- Completed M2 Spec 4 Service Worker + Background Sync ([feature doc](docs/features/%5B20260618%5DGH41_m2-service-worker-background-sync.md)): `web_client` now owns an injected Service Worker, precaches the app shell, serves offline navigations, caches default `GET /tasks` reads with stale-while-revalidate, registers the `psykl-sync` Background Sync tag after enqueue, and lets the Service Worker replay queued writes through the shared replay module while respecting the IndexedDB replay lock. Constituent PRs: [#59](https://github.com/jonpham/PSYKL-System/pull/59) and [#60](https://github.com/jonpham/PSYKL-System/pull/60).
- Completed M2 Spec 3 Sync Engine ([feature doc](docs/features/%5B20260613%5DGH40_m2-sync-engine.md)): `web_client` now queues Task creates in IndexedDB, replays queued mutations with reusable `Idempotency-Key` values, coordinates page and future Service Worker replay with an IndexedDB lock, preserves FIFO ordering across transient retries, moves permanent 4xx failures into `failed_ops`, and renders queued Tasks with a pending affordance plus a permanent-failure toast. Constituent PRs: [#57](https://github.com/jonpham/PSYKL-System/pull/57) and [#58](https://github.com/jonpham/PSYKL-System/pull/58).

## [0.2.0] - 2026-07-24

- Surfaced deployed commit provenance in the PWA ([#64](https://github.com/jonpham/PSYKL-System/pull/64)): `service-task` exposes `GET /version` returning `{ component, commit }` from the `GIT_SHA` baked at image build (falls back to `"dev"`), behind the existing `UserIdGuard`; the web client's `VersionFooter` shows its own `VITE_GIT_SHA` build commit alongside the api commit fetched from `/version`, with an **in-sync / mismatch / api-unreachable** indicator; `GIT_SHA` / `VITE_GIT_SHA` build-args are wired through both Dockerfiles, `cd-publish.yml` (`${{ github.sha }}`), and `docker-compose` (default `dev`). Lets you answer "which commit is deployed?" from the running app without cluster access.
- Documented the homelab GitOps deploy flow. Added `README.md` → **Deploy to k3s (homelab / robin)**: a runbook leading with the three-repo map (`PSYKL-System` chart, `PSYKL-GitOps` cluster desired-state + per-cluster values, `HOME-LAB` bootstrap), the multi-source ArgoCD `Application` assembly, the manual **semver** image-tag bump flow (migrating off raw-SHA pinning), a stale-pin gotcha, and the validation command set. Recorded the architecture as [ADR-M2-010](docs/ARCHITECTURE.md) and retro-recorded the pre-existing helm-hardening commits `feat(helm): support image pull secrets` and `fix(helm): support robin ingress api path` (landed on `main` 2026-06-29 outside a Spec). Rescoped Milestone M4 to **auth + multi-tenant isolation only** — the homelab-deployment deliverable is handled ahead of M4. Deferred image-tag write-back automation to the backlog.
- Completed M2 Spec 2 PWA IndexedDB Store + `useSyncExternalStore` ([feature doc](docs/features/%5B20260612%5DGH39_m2-pwa-indexeddb-store.md)): `web_client` now owns a versioned IndexedDB database named `psykl` with `tasks`, `sync_queue`, `sync_meta`, and `failed_ops` stores; Task UI reads through `useTasks()` backed by React `useSyncExternalStore`; cold-start hydration writes `GET /tasks?include_deleted=1` rows into IndexedDB; same-tab writes call `notifyTasksChanged()` and cross-tab invalidation uses `BroadcastChannel('psykl-idb')`; `TaskList`, `TaskCreateForm`, and `App` no longer maintain fetch-owned Task state. Constituent PRs: [#53](https://github.com/jonpham/PSYKL-System/pull/53) and [#54](https://github.com/jonpham/PSYKL-System/pull/54).
- Completed M2 Spec 1 service-task PATCH/DELETE + LWW + Idempotency ([feature doc](docs/features/%5B20260610%5DGH38_m2-service-task-patch-delete-lww-idempotency.md)): `Task.id` is now client-supplied UUID v7 entity identity on create; Task rows carry `completed_at`, `updated_at`, `server_updated_at`, and `deleted_at`; `PATCH /tasks/:id` and `DELETE /tasks/:id` use client `updated_at` for Last-Write-Wins reconciliation with stale writes returning the current row; soft-delete tombstones are hidden from default `GET /tasks` and exposed through `include_deleted=1`; mutating Task routes require `Idempotency-Key` and replay matching responses for 24 hours or return `409` on same-key/different-body conflicts. Constituent PRs: [#44](https://github.com/jonpham/PSYKL-System/pull/44), [#45](https://github.com/jonpham/PSYKL-System/pull/45), [#46](https://github.com/jonpham/PSYKL-System/pull/46), [#47](https://github.com/jonpham/PSYKL-System/pull/47).

## M1 Bootstrap Spec 6 Shipped - 2026-06-09

- Completed M1 Spec 6 CD Release Pipeline ([feature doc](docs/features/%5B20260520%5DGH7_m1-cd-release-pipeline.md)): three GitHub Actions workflows + a Helm chart wire M1's distribution story. `cd-publish.yml` builds `service-task` + `web_client` container images on every merge to `main` and pushes to GitHub Container Registry with `:{sha}` and `:latest` tags. `cd-subtree-sync.yml` force-pushes both component subtrees to their downstream mirror repositories `jonpham/PSYKL-Client_WEB-PWA` and `jonpham/PSYKL-API_Tasks` (per Decision #16 as re-opened by Decision #35) using a fine-grained `SUBTREE_PUSH_TOKEN` PAT — the documented AGENTS.md force-push exception. `cd-release.yml` triggers on `v*.*.*` tags to add `:{semver}` image tags (third tag per Decision #30) and create a GitHub Release with the packaged Helm chart attached. The Helm chart at `deploy/helm/` is single-replica per Premise 8 with PVC-backed pglite persistence, sibling Deployments + Services for `service-task` and `web_client`, and an optional disabled-by-default Ingress. Decision #16 narrow-scope re-open (new Decision #35) changes mirror repo names from the mechanical `psykl-{web_client,service-task}` to surface-descriptive `PSYKL-Client_WEB-PWA` + `PSYKL-API_Tasks`. Constituent PRs: [#32](https://github.com/jonpham/PSYKL-System/pull/32), [#33](https://github.com/jonpham/PSYKL-System/pull/33); Spec integration [#31](https://github.com/jonpham/PSYKL-System/pull/31).

## M1 Bootstrap Spec 5 Shipped - 2026-05-29

- Completed M1 Spec 5 CI Test Pipeline ([feature doc](docs/features/%5B20260520%5DGH6_m1-ci-test-pipeline.md)): GitHub Actions now runs the full M1 test pyramid on Pull Requests to `main` and Spec integration branches.
