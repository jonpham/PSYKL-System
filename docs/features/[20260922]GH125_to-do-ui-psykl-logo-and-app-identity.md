# PSYKL logo and app identity

## User Story

As anyone running PSYKL — in a browser tab, on an iOS home screen, or from an Android launcher — I
want the app to carry its own mark, so that I can find it among everything else open on my device
and it stops looking like an unfinished page.

## Features

1. The browser tab shows the PSYKL mark. It previously showed nothing: `index.html` pointed
   `rel="icon"` at `/pwa-icon.png`, **a file that has never existed** in `public/` —
   [#125](https://github.com/jonpham/PSYKL-System/issues/125).
2. The tab icon follows the viewer's theme. `favicon.svg` carries its own `prefers-color-scheme`
   rule, so the mark inverts to white ink on a dark tab strip; `favicon.ico` is the fallback for a
   browser that refuses an SVG icon.
3. An installed PWA shows the mark on the iOS home screen and in the Android launcher, with the
   maskable pair carrying the safe-zone padding a launcher crops into.
4. **The home-screen tile follows Settings → Appearance.** An explicit Light or Dark choice wins
   outright; System defers to the device and re-points if the device flips while the app is open.
5. The mobile header and the open sidebar both lead with the mark instead of a hamburger and a
   dismiss glyph. It is inlined SVG filled with `currentColor`, so one asset serves every theme and
   both contrast modes.
6. Past 768 px the sidebar is permanent, so its close control is gone — replaced by a static brand
   heading, out of the tab order and out of the accessibility tree rather than merely invisible.
7. Icon renditions are generated by a committed script, so the next logo revision is one command.

## Verification Steps

**Associated E2E test:** `e2e/app_identity.e2e.spec.ts` (eight tests).

**Manual verification**

_Setup / Preconditions_ — the compose stack built and served on the workstation's LAN IP via an
untracked `docker-compose.override.yml`, reachable from an iPhone on the same Wi-Fi.

_Steps_

1. Open the app in a desktop browser and look at the tab; switch the OS between light and dark.
2. Narrow the window below 768 px and open the navigation from the header; widen it past 768 px.
3. On the iPhone, set Settings → Appearance to **Dark**, then delete any existing home-screen icon
   and re-add the app from Safari.
4. Repeat with Appearance set to **Light**.

_Expectation_ — the tab carries the mark and inverts with the OS theme; the mobile header and open
sidebar lead with the mark while the desktop sidebar offers no close control; the installed tile
matches the appearance chosen in step 3 and step 4.

> **An icon already on the home screen never changes.** iOS bakes the web-clip icon at _Add to Home
> Screen_ time, so a new choice only takes effect on a fresh add. This is a property of iOS web
> clips, not a defect.

## Design Decisions

- **The mark is inlined SVG at `currentColor`, not a PNG.** It sits beside live "PSYKL" text and
  must follow appearance and both contrast modes; one inlined asset does that with no rendition per
  palette. It is `aria-hidden` — the control or heading around it carries the name.
- **The desktop/mobile header swap is structural, not a hidden button.** Both the close button and
  the brand heading are rendered, and the existing `@container psykl-shell (min-width: 768px)` query
  decides which is `display: none` — which removes it from the tab order and the accessibility tree.
  `visibility: hidden` would not have been enough.
- **Icon coverage is per surface, measured rather than estimated.** The delivered pack framed every
  rendition at ~54% of its canvas; once iOS adds tile padding and a browser shrinks the favicon to
  16 px, the mark read as a speck. Now 82% for the iOS tile, 86% for the Android `any` icons, 94%
  for the favicon. **Maskable icons stay at 56% deliberately**: a launcher crops to a shape of its
  choosing and guarantees only the centre 80% circle, so a square mark cannot exceed 80%/√2 there.
- **The app chooses the home-screen tile; Safari does not.** There is no dark variant of
  `apple-touch-icon` for an installed web app and no colour-scheme selector for manifest icons. What
  does work is that Safari reads the link out of the **live document** at _Add to Home Screen_ time,
  so the app rewrites its `href`. A `media="(prefers-color-scheme: dark)"` variant was shipped first
  as a probe and removed once this landed — nothing now rests on undocumented behaviour.
- **`HeaderGlyph`'s `menu` and `close` paths are retained** although no production module uses them;
  `src/experiment/apple-reminders-ux/` keeps its own copy, and the glyphs remain covered.

## Defects fixed along the way

- **A saved appearance was ignored on every load.** `data-theme` was only stamped when
  `SettingsView` mounted, so a user who chose Dark saw the system theme until they happened to open
  Settings again. Preferences are now applied from `main.tsx`. This was pre-existing, and it was
  load-bearing here: _Add to Home Screen_ can happen at any moment, so the icon link has to be
  correct from startup rather than from first navigation.
- **The manifest declared `purpose: 'any maskable'` on artwork with no safe zone**, so an Android
  launcher cropped into the mark. The two purposes now point at the assets actually drawn for each.

## Architecture Decisions (ADR)

- None. No schema, endpoint, or shared-model change; `service-task` is untouched.
