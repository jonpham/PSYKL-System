# Retrospective — `to-do-ui` (migrate the `apple-reminders-ux` prototype into production)

Six Specs plus seven lightweight `target = production` changes, shipped as `v0.5.0` and closed by
deleting the prototype that started it.

## What went well

1. **Prototype-first paid off.** Three iterations at `/exp/apple-reminders-ux` produced a surface
   that four operator review rounds had already accepted. The five implementing Specs then built a
   known quantity — the design argument had been settled against a running build, not a document.
2. **Rewriting the durable docs _before_ implementation, not after.** The Spec 6 outline originally
   scheduled the `docs/DESIGN.md` rewrite at close-out; the initiative moved it to the front
   (`to-do-ui` DESIGN.md → Decision 2). That removed the window in which an implementing Spec could
   read a stale design doc and build the wrong thing. At close-out the doc needed two corrections,
   not a rewrite — which is the evidence the move worked.
3. **Deletion touched no production module.** Removing 47 experiment files changed nothing under
   `src/components/`, `src/hooks/`, `src/services/`, `src/sync/`, or `src/preferences/`. The
   experiment really was parallel to production rather than a fork of it, which is exactly the
   property the `/exp` seam was designed for.
4. **Lightweight `target = production` absorbed the long tail well.** Seven post-Spec changes
   (#122-#127, #138) shipped against the new surface without an Initiative → Spec → DevTask cycle
   each, and without any reduction in the test floor.

## What went poorly

1. **One iteration's `## Not now` was wrong about the order of work.** `apple-reminders-ui` deferred
   reconciling `docs/DESIGN.md` and `UX.md` "to promotion." That deferral was the thing the
   initiative had to undo first. An experiment that expects to supersede a durable doc should say so
   as an _input_ to promotion, not as work to do afterwards.
2. **Two iterations' verdicts stayed `_Open._` while the work that consumed them shipped.** All
   three iterations were fully absorbed by Specs 1-5, but no verdict was recorded until this
   close-out — so between Spec 1 and Spec 6, the artifact folder said "exploring" about a surface
   that was already in production. A verdict belongs in the promoting Spec's PR, not in the
   retirement Spec's.
3. **Design tokens are imported by `main.tsx` alone.** Any Storybook story rendering `<App />` runs
   with no design tokens at all. Found during #138, fixed only in the files #138 and #127 touched,
   and still open elsewhere. A global stylesheet that only one entry point imports is a trap for
   every test harness that is not that entry point.

## Post-experiment refactor proposals

The experiment's `## Not now` forbade production-module edits for its whole life, so several seams
in the client were left alone on purpose. They are now editable. Each is proposed, none implemented
— all are operator calls, and none is a prerequisite for `todo-experience` Specs 3-7.

| #   | Proposal                                                      | Evidence                                                                                                                                                                                                                                                                                                                                                                                                  | Size           |
| --- | ------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| 1   | One factory for device-local preferences                      | `useActiveList`, `useCompletedVisibility`, and `useAppearance` are three shapes for one job. The first two use a module-level store + `useSyncExternalStore`; `useAppearance` uses per-instance `useState`, so two mounted consumers can disagree — the exact bug `useCompletedVisibility`'s own comment cites as its reason for existing. Latent today only because `SettingsView` is the sole consumer. | S — one file   |
| 2   | Invert the `SettingsView` → `src/experiment` import           | `src/components/SettingsView/SettingsView.tsx:3` imports `ExperimentsIndex` from `src/experiment`. A production component depends on the experimental sandbox; the seam was meant to run the other way. Pass the section in from `Root`/`App` as a slot, or move the Experiments section into the `/exp` surface.                                                                                         | S              |
| 3   | Promote `usePathname`/`navigate` out of `hooks/` into routing | Its doc comment justifies it as "the minimum needed to put the experiment sandbox on its own path." That premise died with the experiment: production now routes five destinations through it (`useDestination`). It is a production router primitive documented as experiment scaffolding.                                                                                                               | S — move + doc |
| 4   | Give task ordering one owner                                  | Ordering is spread over three layers: `useTasks` returns newest-first, `sortTasks` re-sorts oldest-first (its comment still says "the experiment re-sorts rather than asking the shared hook to change"), then `applyHandOrder` overrides inside `TaskList`'s `useMemo`. Collapse into one module the hook and the list both call.                                                                        | M              |
| 5   | Move pending-sync ids behind the hook layer                   | `TaskList.tsx` calls `taskServiceClient.listPending()` directly in an effect keyed on `tasks`, reaching past the hook layer into the service layer to re-derive state `useTasks` is already positioned to own. Extract `usePendingTaskIds`, or fold it into `useTasks`.                                                                                                                                   | S              |
| 6   | Import `styles/tokens.css` where components can see it        | See "What went poorly" #3. Already tracked in `docs/PROJECT_STATUS.md`.                                                                                                                                                                                                                                                                                                                                   | S              |

Proposals 1 and 2 are the two worth doing before `todo-experience` resumes: #1 because Specs 3-7 add
more device-local preferences (sections, ordering, notes) and will otherwise copy a fourth shape,
and #2 because it is the only remaining production → experiment dependency and it is one line.

## Proposed AGENTS.md changes

1. **Record an iteration's verdict in the Spec that promotes it, not in the retirement Spec.**
   Add to the Spec close-out checklist: "If the Spec promoted an experiment iteration, record that
   iteration's verdict and archive its folder in this Spec's PR." Rationale: "What went poorly" #2.
2. **An experiment that expects to supersede a durable doc says so in its feature card.** The
   reconciliation is then an input to the promoting initiative's planning rather than deferred work
   discovered at close-out. Rationale: "What went poorly" #1.
