## Overview

This Spec makes the offline sync queue entity-agnostic and then uses that capability to ship the first new syncable entity: **Lists**. Today `SyncQueueEntry` hardcodes `task_id` (`components/web_client/src/db/idb.types.ts:9`), replay writes every successful response back through `putTask` (`components/web_client/src/sync/replay.ts:99`), and the transport routes every operation to `/tasks` (`components/web_client/src/sync/replay.transport.ts`). Nothing but a Task can round-trip.

After this Spec: the queue carries `entity_type` + `entity_id`, replay dispatches writeback and transport by entity type, a `lists` table exists server-side, a `lists` object store exists in IndexedDB, tasks carry a nullable `list_id`, and the user can create, rename, reorder, and switch between lists — online or offline.

Components touched: `packages/shared-types`, `components/service-task`, `components/web_client`, `e2e/`.

**Not in this Spec:** Recently Deleted, the orphan sweep, and offline queue thresholds all moved to Spec 2. Sections (Spec 3) and drag-to-reorder of _tasks_ (Spec 4) come later — this Spec ships list ordering only, which exercises the fractional-index machinery on a small surface before tasks depend on it.

## Global Constraints

- **No foreign keys on child entities.** `task.list_id` is nullable `text` with no `references()`. The server accepts a `list_id` it has not seen. (Locked: DESIGN.md → Offline Posture.)
- **All entity IDs are client-minted UUID v7.** Server never generates an id. (ADR-M2-001.)
- **Every persisted record carries `user_id`.** Enforced by the existing global guard; every new endpoint gets a negative-path Component test proving header-less requests are rejected.
- **Position keys are `text COLLATE "C"`.** Generated by the `fractional-indexing` package client-side. Postgres byte order must equal JavaScript string comparison.
- **The IndexedDB upgrade migrates in place. It never drains.** A user upgrading while offline must lose zero queued writes.
- **TDD is mandatory.** Failing test → implementation → green → refactor. Tests ship in the same PR as the behavior.
- **≤10 production behavior source files per DevTask PR.** Tests, config, docs, lockfiles, and generated Drizzle migrations are exempt.

### Collation

The generated migration must be hand-edited so `lists.position` is created with `COLLATE "C"`. Drizzle does not emit column collation. The migration SQL reads:

```sql
CREATE TABLE "lists" (
  "id" text PRIMARY KEY NOT NULL,
  "user_id" text NOT NULL,
  "title" text NOT NULL,
  "position" text COLLATE "C" NOT NULL,
  "created_at" timestamp with time zone DEFAULT now() NOT NULL,
  "updated_at" timestamp with time zone NOT NULL,
  "server_updated_at" timestamp with time zone DEFAULT now() NOT NULL,
  "deleted_at" timestamp with time zone
);
ALTER TABLE "tasks" ADD COLUMN "list_id" text;
```

## API

```
POST /lists
Body:     { id: string(uuidv7), title: string(1..100), position: string(1..64), updated_at: string(iso) }
Auth:     `user_id` header enforced by the global guard
Response: 201 + List
Errors:   400 invalid body · 401 missing/blank user_id · 409 duplicate id

GET /lists
Query:    ?include_deleted=true (optional)
Response: 200 + List[]
Errors:   401

PATCH /lists/{id}
Body:     { title?: string, position?: string, updated_at: string(iso) }   // at least one of title/position
Response: 200 + List
Errors:   400 · 401 · 404
          A stale write (updated_at <= stored) is NOT an error: it returns 200 with the
          unchanged row, matching TaskService.patchTask. The client reconciles from the response.

DELETE /lists/{id}
Body:     { deleted_at: string(iso) }
Response: 200 + List (tombstoned)
Errors:   400 · 401 · 404
```

All four routes reuse the existing `Idempotency-Key` header interceptor. No new idempotency machinery.

```ts
async function openPsyklDb(): Promise<PsyklDb> {
  return openDB<PsyklDbSchema>('psykl', CURRENT_SCHEMA_VERSION, {
    upgrade(db, oldVersion, _newVersion, tx) {
      if (oldVersion < 1) {
```

Add the upgrade routine. It rewrites both queue stores in place and creates the lists store:

```ts
function upgradeV1ToV2(
  db: PsyklDb,
  tx: IDBPTransaction<PsyklDbSchema, ArrayLike<StoreNames<PsyklDbSchema>>, 'versionchange'>,
): void {
  for (const storeName of ['sync_queue', 'failed_ops'] as const) {
    const store = tx.objectStore(storeName);
    if (store.indexNames.contains('task_id')) {
      store.deleteIndex('task_id');
    }
    if (!store.indexNames.contains('entity_id')) {
      store.createIndex('entity_id', 'entity_id');
    }
    void store.openCursor().then(async function rewrite(cursor): Promise<void> {
      if (!cursor) {
        return;
      }
      const value = cursor.value as unknown as SyncQueueEntryV1;
      if ('task_id' in value) {
        await cursor.update(migrateQueueEntryV1ToV2(value) as never);
      }
      const next = await cursor.continue();
      return rewrite(next);
    });
  }

  if (!db.objectStoreNames.contains('lists')) {
    const lists = db.createObjectStore('lists', { keyPath: 'id' });
    lists.createIndex('deleted_at', 'deleted_at');
    lists.createIndex('position', 'position');
    lists.createIndex('updated_at', 'updated_at');
  }

  const tasks = tx.objectStore('tasks');
  if (!tasks.indexNames.contains('list_id')) {
    tasks.createIndex('list_id', 'list_id');
  }
}
```

**Interfaces:**

- Consumes: `SyncQueueEntry`, `EntityType` from DevTask 1.
- Produces:

  - `writeBackResponse(entry: SyncQueueEntry, data: unknown, db?: PsyklDb): Promise<void>` in `replay.writeback.ts`

**Why:** supersedes ADR-M2-012. The server tolerates any arrival order (no foreign keys), so stopping the queue at the first transient failure protects nothing and freezes every later write behind it. `replay.ts:127` currently computes `2 ** attempts * 1000` ms with no ceiling and no path to `failed_ops`, so a permanently broken entry retries for weeks.

```ts
import { Inject, Injectable, NotFoundException } from '@nestjs/common';
import type { ListDeleteInput, ListInput, ListPatchInput, List as ListResponse } from '@psykl/shared-types';
import { and, eq, isNull } from 'drizzle-orm';

import { type Db, schema } from '../db/index.js';

export const DB_TOKEN = Symbol('DB');

@Injectable()
export class ListService {
  constructor(@Inject(DB_TOKEN) private readonly db: Db) {}

  async createList(userId: string, input: ListInput): Promise<ListResponse> {
    const [row] = await this.db
      .insert(schema.lists)
      .values({
        id: input.id,
        userId,
        title: input.title,
        position: input.position,
        updatedAt: new Date(input.updated_at),
      })
      .returning();
    if (!row) {
      throw new Error('Insert returned no row');
    }
    return this.toResponse(row);
  }

  async listLists(userId: string): Promise<ListResponse[]> {
    const rows = await this.db
      .select()
      .from(schema.lists)
      .where(and(eq(schema.lists.userId, userId), isNull(schema.lists.deletedAt)));
    return rows.map((row) => this.toResponse(row));
  }

  async patchList(userId: string, id: string, input: ListPatchInput): Promise<ListResponse> {
    const existing = await this.requireList(userId, id);
    const incoming = this.clampFutureTimestamp(new Date(input.updated_at));

    // Last-Write-Wins, matching TaskService.patchTask: a write that is not newer is
    // a silent no-op returning the stored row, NOT a 409. The client reconciles from
    // the response body. Diverging here would give Lists different semantics to Tasks.
    if (incoming.getTime() <= existing.updatedAt.getTime()) {
      return this.toResponse(existing);
    }

    const [row] = await this.db
      .update(schema.lists)
      .set({
        ...(input.title === undefined ? {} : { title: input.title }),
        ...(input.position === undefined ? {} : { position: input.position }),
        updatedAt: incoming,
        serverUpdatedAt: new Date(),
      })
      .where(and(eq(schema.lists.id, id), eq(schema.lists.userId, userId)))
      .returning();
    return this.toResponse(row!);
  }

  async deleteList(userId: string, id: string, input: ListDeleteInput): Promise<ListResponse> {
    await this.requireList(userId, id);
    const [row] = await this.db
      .update(schema.lists)
      .set({ deletedAt: new Date(input.deleted_at), serverUpdatedAt: new Date() })
      .where(and(eq(schema.lists.id, id), eq(schema.lists.userId, userId)))
      .returning();
    return this.toResponse(row!);
  }

  private async requireList(userId: string, id: string) {
    const [row] = await this.db
      .select()
      .from(schema.lists)
      .where(and(eq(schema.lists.id, id), eq(schema.lists.userId, userId)));
    if (!row) {
      throw new NotFoundException('List not found');
    }
    return row;
  }

  private toResponse(row: typeof schema.lists.$inferSelect): ListResponse {
    return {
      id: row.id,
      user_id: row.userId,
      title: row.title,
      position: row.position,
      created_at: row.createdAt.toISOString(),
      updated_at: row.updatedAt.toISOString(),
      server_updated_at: row.serverUpdatedAt.toISOString(),
      deleted_at: row.deletedAt?.toISOString() ?? null,
    };
  }
}
```

Copy `clampFutureTimestamp` from `TaskService` into a shared helper both services import — do not duplicate the implementation. There is no stale-write exception in this codebase and this Spec does not introduce one.

```ts
async function putList(list: ListRecord, db?: PsyklDb): Promise<void> {
  return withDb(db, async (database) => {
    await database.put('lists', list);
  });
}

async function listLists(db?: PsyklDb): Promise<ListRecord[]> {
  return withDb(db, async (database) => database.getAllFromIndex('lists', 'position'));
}

async function getList(id: string, db?: PsyklDb): Promise<ListRecord | undefined> {
  return withDb(db, async (database) => database.get('lists', id));
}
```

- [ ] **Step 5: Write the hook**

Create `components/web_client/src/hooks/useLists.ts`, following the `useTasks.ts` `useSyncExternalStore` pattern:

```ts
import { generateKeyBetween } from 'fractional-indexing';
import { useCallback, useSyncExternalStore } from 'react';
import { v7 as uuidv7 } from 'uuid';

import { listLists, putList } from '../db/idb';
import type { ListRecord } from '../db/idb.types';
import { enqueue } from '../sync/replay';

function useLists() {
  const lists = useSyncExternalStore(subscribeToLists, getListsSnapshot);

  const createList = useCallback(
    async (title: string): Promise<ListRecord> => {
      const last = lists.at(-1) ?? null;
      const now = new Date().toISOString();
      const list: ListRecord = {
        id: uuidv7(),
        user_id: 'local',
        title,
        position: generateKeyBetween(last?.position ?? null, null),
        created_at: now,
        updated_at: now,
        server_updated_at: now,
        deleted_at: null,
      };
      await putList(list);
      await enqueue({
        body: { id: list.id, title: list.title, position: list.position, updated_at: list.updated_at },
        entityId: list.id,
        entityType: 'list',
        op: 'create',
      });
      notifyListSubscribers();
      return list;
    },
    [lists],
  );

  const moveList = useCallback(
    async (id: string, before: ListRecord | null, after: ListRecord | null): Promise<void> => {
      const position = generateKeyBetween(before?.position ?? null, after?.position ?? null);
      const updated_at = new Date().toISOString();
      const existing = lists.find((list) => list.id === id);
      if (!existing) {
        return;
      }
      await putList({ ...existing, position, updated_at });
      await enqueue({ body: { position, updated_at }, entityId: id, entityType: 'list', op: 'patch' });
      notifyListSubscribers();
    },
    [lists],
  );

  const renameList = useCallback(
    async (id: string, title: string): Promise<void> => {
      const updated_at = new Date().toISOString();
      const existing = lists.find((list) => list.id === id);
      if (!existing) {
        return;
      }
      await putList({ ...existing, title, updated_at });
      await enqueue({ body: { title, updated_at }, entityId: id, entityType: 'list', op: 'patch' });
      notifyListSubscribers();
    },
    [lists],
  );

  return { createList, lists, moveList, renameList };
}

export { useLists };
```

Reuse the `BroadcastChannel` subscribe/notify helpers `useTasks.ts` already defines rather than writing a second copy — extract them to a shared module if they are currently private to `useTasks.ts`.

## Decisions made during spec drafting

- **The Spec integration branch is `spec/todo-experience-s1-sync-queue-and-lists`.** The tag is `todo-experience`, matching `AGENTS.md` → Git Conventions for purpose-tagged milestones.
- **`MAX_REPLAY_ATTEMPTS = 10`**, roughly 17 minutes of cumulative backoff before an entry is quarantined. Not specified by the initiative design; chosen so a transient outage of a few minutes never surfaces as a permanent failure.
- **The default list is created client-side, not seeded server-side.** A server seed would need to run per user before any request, and the client already owns id generation. Guarded by a `sync_meta` flag against a two-tab race.
- **`active_list_id` lives in `sync_meta`.** Same device-local store the initiative assigned to theme choice and section collapse state.
- **List ordering ships in this Spec, task ordering in Spec 4.** Exercising fractional indexes on ~5 lists before ~200 tasks depend on them is deliberate.
- **DevTask 3 does not depend on DevTasks 1-2** and can run in a parallel worktree.

## Open Questions / Risks

- **The v1→v2 upgrade is the first migration this app has ever run.** `CURRENT_SCHEMA_VERSION` has been `1` since M1. The integration test with a real v1 fixture is the mitigation; do not weaken it to a unit test.
- **`COLLATE "C"` is hand-edited into a generated migration.** A later `drizzle:generate` could silently drop it. The collation integration test is the guard — if it ever fails, check the migration first.
- **Cursor iteration inside an IndexedDB `versionchange` transaction** is the fiddliest code in this Spec. If the upgrade proves unreliable across browsers, the fallback is to read all rows, close, and rewrite on first open at v2 — slower but simpler.
- **`fractional-indexing` is a new dependency.** Small, no transitive deps, MIT. Add it to `docs/STACK.md` at Spec close-out.
