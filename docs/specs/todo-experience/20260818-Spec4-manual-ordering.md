# Manual Ordering — Implementation Spec

> **Outline.** Per-Step TDD detail is written when this Spec starts.

**Date:** 2026-08-18
**Initiative:** `todo-experience`
**Spec:** 4/7
**Spec User Story:** _As the operator, I drag tasks into the order I want and that order survives reload, section moves, and a concurrent rearrangement on a second offline device._
**Time-box:** ~4 days human / ~1-2 Claude Code sessions

---

## Overview

The hero interaction. Tasks gain a fractional-index `position`, generated by the `fractional-indexing` package already proven on lists in Spec 1. A reorder writes **one row**, so two devices rearranging different parts of the same list do not collide.

This Spec carries the initiative's stated success criterion: _a hand-arranged list survives a concurrent reorder on two offline devices with no lost arrangement_ — tested, not assumed.

---

## Data Model

`tasks` gains `position text` (`COLLATE "C"` in the migration). Backfill assigns positions in `created_at` order so existing tasks keep their current apparent order.

No IndexedDB schema bump — the `tasks` store is schemaless per record; a `position` index is added at v4.

### DevTask 15 — the interaction

Long-press arms the drag; a grip fades in at the trailing edge; the lifted row takes `--bg-pressed`; an insertion gap opens that other rows animate around. Beats the Reminders defect the design cites.

**Two implementation notes carried from the 2026-08-13 prototype**, where both were found the hard way:

- Set `touch-action: none` on the armed row, and handle `pointercancel`. Without both, the browser reclaims a vertical drag as a scroll, fires `pointercancel` instead of `pointerup`, and strands the row mid-drag permanently.
- Move rows with a FLIP transform after the DOM mutation. Reordering the DOM alone does not animate.

### DevTask 16 — accessibility

Modifier + arrow keys move a focused row, announced through an ARIA live region. Drag-only reorder is inaccessible, and reorder is the interaction this product cares most about.

## Test Plan

- **Unit:** position generation between neighbours, at the head, and at the tail; cross-section move recomputes both `section_id` and `position`.
- **Integration:** `ORDER BY position` matches JavaScript sort (reuses the Spec 1 collation guard); reorder writes exactly one row.
- **Component:** Storybook play function driving a pointer drag; keyboard reorder announces via live region.
- **E2E:** `e2e/task_reorder.e2e.spec.ts`, including the two-device concurrent-reorder test. This is the hardest test in the milestone and uses the multi-device harness M2 Spec 6 shipped.

## Open Questions / Risks

- **The two-device test is the milestone's success criterion.** Budget real time for it; it exercises the offline harness, fractional indexes, and Last-Write-Wins together.
- A reorder concurrent with a _section move_ of the same task still resolves by Last-Write-Wins. Expected, and worth an explicit test asserting the loser is a whole coherent position rather than a hybrid.
